# Module implementation

When assigned an implementation module:

- Read its objective, inputs, deliverable, and acceptance criteria. Write a short MODULE_PLAN.md before changing task code, then implement that plan.
- Request **module task decomposition** from ROOT if the assignment contains several independently testable deliverables or cannot reasonably fit your remaining execution budget. Use manager-notify, give the reason and proposed boundaries, preserve progress, and stop at a safe boundary. ROOT decides reassignment; do not launch child workers yourself.
- Commit the deliverable and relevant checks. Report results and remaining gaps in RESULT.json against the module's acceptance criteria. Other unfinished modules do not make this module fail.
